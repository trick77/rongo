# A standing instruction outranks the prompt

**Status: measured 2026-09-18 on the flow corpus, BA audience, MiMo Pro,
`TestEvalMeasureAnswers` twice per arm, one database. The understanding
prompt with the memory fields is within judge noise of the one without; a
seeded "Never draw flowchart diagrams." took flowcharts from 7 to 1 over
the same twenty answers and left sequence diagrams standing. Shipped.**

## What was measured

Memory adds fields to the understanding prompt on every turn
(`understandMemoryFields`, `backend/internal/ask/understand.go`) and, for
a reader with rules, a block at the end of the answer prompt
(`memory.Block`). Two questions: does the changed understanding prompt cost
answers, and does the block actually win against the prompt's own diagram
rule, which was tuned the day before to draw more (`2026-09-17-ba-diagrams.md`).

Arms, all from one worktree on one `/tmp/rongo-flow.db` (482 files, 3516
chunks, 30 questions), `hack/run-flow-eval.sh 'TestEvalMeasureAnswers$'`:

- `BACKEND_EVAL_MEMORY=0`: no holder on the context, the understanding
  prompt byte for byte as on master (a test asserts that).
- `BACKEND_EVAL_MEMORY=1`: the prompt that ships, no rules.
- `BACKEND_EVAL_MEMORY_RULES="Never draw flowchart diagrams."`: the block
  with one rule in every answer.

## Reading

- Rubric and citations move by one or two questions between arms, the
  same spread two passes of one arm show. The memory fields cost nothing
  measurable; the understanding call grows by a few hundred tokens.
- The rule is obeyed in six of seven places a flowchart was drawn without
  it, and the model did not stop drawing altogether: sequence diagrams went
  up, which is the block saying "no flowcharts" and not "no pictures". The
  one survivor ("Which service decides whether a payment is authorised")
  is one answer in forty; a rule is a prompt, not a filter.
- Tokens per pass are flat (280-310k), so the block is not paid for twice.
