# An M/TEXT template is chunked by block, and its includes are followed by stem

**Status: built 2026-11-11. `.mtxm`/`.mtxt` are language `mtext`;
`symbols.ExtractMText` emits a head anchor (stem + title), one anchor per
top-level control or layout block and one for the preview text; `edges`
records includes and `ask` follows them by stem, own repository first, then
the libraries the turn may reach. On a private estate's ten questions, two
invocations of two runs each in one database: rubric 66/86 before, 71/84
after, cited parts 28/44 to 32/42. The two questions whose answer needs a
block from the shared library went from 5/16 to 9/16 and from 4/12 to 6/12.
Three of ten were answered with a card in every run, in both arms.**

## Why

M/TEXT (kwSoft) letter templates were plain text to rongo: no language,
600-token windows, no symbol, no edge from a template to the blocks it
includes. Templates are thin wrappers; the logic sits in included blocks,
four of five of them in a shared library repository. A question about what a
letter shows needed both files and reached the second only by search luck.

## What was built

- `symbols.ExtractMText`: head anchor from line 1 with the first prose
  comment as title; top-level `.IF/.WHILE/.FOREACH/.SWITCH/.WITH` and
  `.TABLE/.TEXTFRAME` blocks; preview anchor after a top-level `.EOJ`. An
  unbalanced file keeps the head alone. CR and BOM stripped.
- Chunking: `.DSC` is the only doc comment in M/TEXT. A `.DSC` run directly
  above a block joins that block; `#` (include) and `*` (variable) lines
  never move.
- `edges`: kind `include` from include lines, `.SET`/`.NEW` values and
  `.INC`, never from comments; a language variable is one `{lang}` token.
  `include` is not a neighbour edge. `edges.Included` resolves by
  `files.stem` (Unicode-folded, indexed), own repository first per include
  site, else a reachable library; a language site lands one variant (de, fr,
  it, en). Heads are not symbols, so the name walk never resolves a stem.
- `ask`: includes are followed inside the symbol walk, reason `include:`; a
  refused include does not end the walk.
- `.translation` counts as data. Migration 0041 adds `files.stem` and
  re-indexes.

## Corpus

Three repositories as snapshots: a business project (3316 files), its shared
library (722) and an application repository holding copies of some templates
(2182). 2224 template files. Found on the corpus, not in the plan:
`.TEXTFRAME` is a block (147 balanced), `.SECTION` is not; one repository
uses CRLF; 115 files open a block on line 1; six files open a table in both
branches of an `.IF` and close it once after it, so layout blocks are
tracked leniently. 9632 include sites, 1592 of them language sites.

from its cache. "First cut" is this branch before review: no `.DSC` rule,

The `.INC` question: in the first cut the comment naming the block sat on
the line above it and landed in the previous chunk, which pulled the answer
to an unrelated block (4/8). With `.DSC` joining its block, the answer cites
the template and the included one in every run. The baseline's 8/8 came
from a sibling template carrying the same rule. Sources per answer on the
include questions rose from 21-24 to 36-89 at a similar token count.

## What it does not do yet

- An include lands on the target's head chunk only; the target's own blocks
  arrive through search. Landing its block chunks too was measured off:
  `2026-11-13-mtext-include-blocks.md`.
- Three questions get a project card in every run of all arms. The templates
  also exist as copies in a second project; the card is routing, not
  chunking, and the rubric measures seven of ten until it is resolved.
- The eval index ignored `BACKEND_INDEX_EXCLUDE` until this branch's base
  wired the selector into `TestEvalIndex`; all numbers above are on the
  corrected index.
