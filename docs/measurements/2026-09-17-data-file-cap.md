# The data ceiling: why json and xml above 8 KiB are skipped, and yaml is not

**Status: sized on 2026-09-17 over the tracked files of rongo and two nearby
repositories (a Vite/Go app, a Java service). Not an eval run: no retrieval
number moved, this fixes what enters the corpus. `DefaultSelectOptions().MaxDataBytes = 8 << 10`,
`BACKEND_INDEX_MAX_DATA_FILE_BYTES`.**

## The problem

`libs/schadenmeldung-lib/src/lib/i18n/generated-de-CH.json` was indexed and
cited. A translation catalogue matches every domain word in the question in
both lanes, so it outranks the code that does the thing. The selector knew lock
files, `.min.*`, build directories and the `Code generated ... DO NOT EDIT`
marker; it knew nothing about a file *called* generated, an `i18n/` directory,
csv, source maps, snapshots, or a json blob of two thousand rows.

The json that answers a question about how something is built is under 1 KB.
The data starts at 30 KB. Between them sit only fixtures. 32 KiB was the first
proposal and was judged too generous; 8 KiB keeps every config above and cuts
every blob, with the eval fixtures landing on the data side, which is where
they belong for a reader asking about rongo.

Tracked yaml, for the opposite argument:

| file | bytes |
|---|---|
| `repos.example.yaml` | 11460 |
| `compose.yaml` | 9246 |

Both files above the ceiling are hand-written configuration and exactly what a
"how is X deployed" question needs. A Helm `values.yaml` runs to 20 KB for the
same reason. Yaml is therefore not under the ceiling at all.

## What the rule is

Three groups in `backend/internal/indexer/select.go`, applied after the
operator's `BACKEND_INDEX_EXCLUDE` and the vendored directories, name before
size:

1. **Generated by name, any size** (`generated`): `generated` as a word of
   the basename (`generated-de-CH.json`, `schema.generated.ts`; not
   `GeneratedIdEntity.java`); a segment in `generated`, `__generated__`,
   `__snapshots__`, `coverage`, `.idea`, `.gradle`, `.nx`, `.angular`; a
   catalogue format under `i18n`, `locales`, `locale`, `translations` (the
   `src/i18n/index.ts` that wires the library stays); a generator suffix
   (`.pb.go`, `_pb2.py`, `.g.dart`, `.designer.cs`, ...); any `.lock` or
   `.sum`. The head marker now also matches `@generated` and
   `<auto-generated`, the tag forms; the prose "auto-generated" does not
   count, a README says it about a generator.
2. **Data formats, any size** (`data`): `.csv`, `.tsv`, `.jsonl`, `.ndjson`,
   `.geojson`, `.parquet`, `.avro`, `.map`, `.snap`, `.har`, `.log`, `.xlf`,
   `.xliff`, `.po`, `.pot`, `.mo`, `.resx`, `.strings`, `.svg`, `.pdf`,
   `.ipynb`.
3. **Long data file** (`data`): `.json`, `.json5`, `.xml`, `.xsd`, `.wsdl`,
   `.plist` above the ceiling. Exempt: manifests (`pom.xml`, `package.json`,
   `project.json`, `nx.json`, `angular.json`, `tsconfig*.json`, ...), since
   the repository's structure is read from them and a parent pom outgrows any
   ceiling; and hand-written configuration that routinely runs past 8 KiB
   (`applicationContext.xml`, `persistence.xml`, `web.xml`, `logback*.xml`,
   `log4j2.xml`, `appsettings*.json`) plus Camunda `*.bpmn20.xml` process
   models, whose diagram geometry alone passes any ceiling.

Every one of these needs only the path and the size, so the boot sweep
(`Indexer.Sweep`) retires what an older build embedded without reading git.

## What would change the number

A workspace whose useful json lands between 8 and 30 KB. `angular.json` of a
large Angular workspace is the candidate; it is on the manifest list. Anything
else that turns up is a raise of `BACKEND_INDEX_MAX_DATA_FILE_BYTES` followed
by a reset of the repository: the sweep only retires, it never re-admits, and
an incremental run only visits changed paths. The index log names the ceiling
in the skip line; the file row carries `data` alone, like every other skip.
