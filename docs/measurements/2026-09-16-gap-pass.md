# A directed gap pass after Gather: measured, does not ship as built

**Status: measured 2026-09-15 and 2026-09-16 on the flow corpus (gathered twice, answers judged twice) and the Go corpus (twice, one run lost to upstream). The pass costs the walk its reserve and asks mostly for local variables and framework names; flow parts fall 28 -> 27, 26 with the reranker and 27 -> 24, 24 without. The answer judge is level with the baseline. The code stays on the branch as a harness-only arm; the product is unchanged.**

## Why

answer-quality-investigation.html step 5b: the tool-loop diagnostic showed a model that finds `calculateTotal` and never asks where `unitPrice` comes from. The pass turns that question into extraction: after the symbol walk and the crossings, one short-gate JSON call lists at most eight names the mechanism depends on whose definition is not among the sources (symbol, route, destination, property), each resolved deterministically through the symbols table, the integration tokens and the strict keyword rung, landing chunks admitted under a reserve of one twelfth of the budget. A failed call changes nothing. Stores nothing.

## What it says

- **The reserve is the cost and the names are the waste.** Holding back a twelfth of the budget takes a part off the walk on the corpus the pass was written for, and what the model lists is not the missing definition but the visible locals. The prompt's "leave out anything defined in a source below" did not hold against a Spring service's field soup.
- **The invoice question moving to 3/3 twice on fewer sources is the one thread worth pulling**, and it is not the gap pass's mechanism: it is the answer reading a smaller, tighter set. That points at pruning what the walk hands the answer, not at adding to it.
- If the idea is tried again: no reserve (run the pass only when the walk stopped short of the budget), a prompt that names the kinds of things NOT to ask for with examples from this log, and no keyword fallback (a name the index does not know as a symbol or a token is not a gap the pass can fill).
- Kept on the branch, off in the product, like `RouteSuffix` and `WholeFileTokens`: `BACKEND_EVAL_GAP=1` in the harness re-runs it.
